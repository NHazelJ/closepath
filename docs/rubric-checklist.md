## Project 3 (200 pts + up to 6 bonus)

### Application Quality (40)

- [ ] **Feature completeness, 15:** 2+ roles (we have 4), F1 to F5 working end to end.
- [ ] **UX and polish, 10:** professional, responsive, loading, empty and error states.
- [ ] **Production deployment, 15:** live on Vercel, clean URL, env vars managed.

### Claude Code Mastery (55)

- [x] **CLAUDE.md with `@imports`** (part of the 8 pts).
- [ ] **CLAUDE.md keeps evolving in git:** v3 and later as features, skills and hooks land.
- [ ] **Auto-memory usage** with evidence (screenshots or session log).
- [ ] **Skills, 10:** 2+ in `.claude/skills/` (`/add-feature`, `/create-pr`), with team usage evidence and one iterated v1 to v2.
- [ ] **Hooks, 8:** 2+ in `.claude/settings.json`, including a PreToolUse or PostToolUse hook (format or lint on edit, block `.env`) and a quality hook (Stop hook that runs tests).
- [ ] **MCP, 8:** 1+ server shared via `.mcp.json` (Playwright or GitHub), with usage evidence.
- [ ] **Agents, 8:** a sub-agent in `.claude/agents/` (security-reviewer) with evidence in PRs.
- [ ] **Parallel development, 5:** 2+ features built at the same time in git worktrees, visible in branch history.
- [ ] **Writer/reviewer + C.L.E.A.R., 8:** 2+ PRs where one agent writes and another reviews, C.L.E.A.R. comments, and AI disclosure.

### Testing and TDD (30)

- [ ] **TDD workflow, 12:** red, green, refactor in git for 3+ features (F2 scoring, F5 overlap, F4 routing).
- [ ] **Coverage and pyramid, 10:** 70%+ coverage; unit, integration and E2E (Playwright).
- [ ] **Test quality, 8:** behavior and edge cases, not happy paths only.

### CI/CD and Production (35)

- [ ] **Pipeline, 15:** all 8 stages green on `main`.
  - [ ] Lint (ESLint + Prettier)
  - [ ] Type check (`tsc --noEmit`)
  - [ ] Unit and integration tests
  - [ ] E2E (Playwright)
  - [ ] Security scan (`npm audit`)
  - [ ] AI PR review (`claude-code-action`)
  - [ ] Vercel preview deploy
  - [ ] Production deploy on merge to `main`
- [ ] **AI PR review, 10:** `claude-code-action` with structured, actionable output.
- [ ] **Security gates, 10:** 4+ gates (Gitleaks, npm audit, CodeQL or the security sub-agent, security criteria in the DoD), plus OWASP in CLAUDE.md.
  - [x] OWASP Top 10 in `CLAUDE.md` and `docs/security.md`.
  - [x] Security criteria in the Definition of Done (`docs/PRD.md` section 6).

### Pair Process (25)

- [ ] **Sprints, 10:** 2+ sprints with planning, velocity (story points) and retrospectives in `docs/sprints/`.
- [ ] **GitHub workflow, 8:** branch per issue, reviewed PRs, AI disclosure, **5+ PRs per partner**.
  - [x] Branch protection on `dev` and `main` (PR required, merge commits only).
- [ ] **Async standups, 7:** 3+ per sprint per partner in `docs/standups/`.
- [ ] **GitHub Issues** with acceptance criteria as testable specs.
- [ ] **Balanced contributions:** commits and reviews from both partners (grades can shift up to ±10%).

### Documentation and Demo (15)

- [ ] **README, 3:** clear, with a Mermaid architecture diagram and setup instructions.
- [ ] **Blog post, 3:** published on Medium or dev.to, covering the AI workflow and technical decisions.
- [ ] **Video, 6:** 5 to 10 minutes on the app and the Claude Code workflow, with narration.
- [ ] **Reflections, 3:** 500 words per partner, with specific Claude Code insights.
