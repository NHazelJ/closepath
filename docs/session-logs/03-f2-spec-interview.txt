⏺ AskUserQuestion
  Q1 [Time rules] F2 time rules: how should the scoring recency windows (1 / 7 / 30 days) and the call list's "not contacted today" be measured?
     - Elapsed + LA date (Recommended): Recency uses elapsed time: age <= 24h, <= 7x24h, <= 30x24h, boundaries inclusive. "Today" is the same calendar date in America/Los_Angeles, so a call at 11pm yesterday doesn't hide the lead this morning. No DST bugs in scoring.
     - LA calendar days for both: Recency counts calendar dates in America/Los_Angeles ("1 day" = today or yesterday). Matches how agents talk, but a lead's score jumps at midnight and the code must handle DST.
     - Elapsed time for both: Recency is elapsed time, and "contacted today" means the last 24 hours. Simplest code, but a lead called at 4pm yesterday stays hidden until 4pm today.
  Q2 [Showings] F2-AC5 showings: which showing requests earn the +25, and does a cancelled request still count as recent buyer activity?
     - Literal PRD (Recommended): +25 if any request is REQUESTED, CONFIRMED or DECLINED ("not cancelled"). A decline is the agent's choice, and the buyer still wants to see the home. Every request, cancelled or not, counts as activity on its request date.
     - Only live showings: +25 only for REQUESTED or CONFIRMED. A DECLINED or CANCELLED request gets no bonus but still counts as activity on its request date.
     - Ignore cancelled fully: +25 for anything not cancelled, and a cancelled request counts for nothing, not even recency.
  Q3 [Input shape] F2 scoring input: what shape should `scoreLead()` take? (Both options are plain types, not Prisma models, with `now` passed in.)
     - Raw event lists (Recommended): `{ status, phone, inquiries: {at}[], savedHomes: {savedAt}[], showingRequests: {requestedAt, status}[] }`. The domain code does the counting, caps and recency, so all of it gets TDD and property tests. savedHomes are the homes saved right now; an unsave removes one.
     - Pre-aggregated counts: `{ status, hasPhone, inquiryCount, savedHomeCount, hasLiveShowing, lastBuyerActivityAt }`. The DAL counts in SQL and the domain code only adds points. Cheaper queries, but the counting logic gets no unit tests.
  Q4 [Storage] F2 score storage (for the later DAL and schema): should the score be stored, or computed when it's read?
     - Compute on read (Recommended): No score column. `/agent/leads` scores the agent's leads per request (fine for under 200 demo leads). Recency decays as time passes, so a stored score would go stale. This also makes F2-AC8 hold by construction.
     - Store and refresh: Add a `score` column, recomputed on every lead event and by the daily cron. SQL can sort by it, but it is stale between events and needs a schema change and a job.
